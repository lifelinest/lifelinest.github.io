## 三、5分钟实战：从零制作首个 Skill（Go 单元测试生成）

![doubao_image_6_1781855371374.png](/images/doubao_image_6_1781855371374.png)
本次实战选用[**Go 语言**](https://go.dev/)**单元测试自动生成技能**作为案例，该场景通俗易懂、逻辑简洁、落地效果直观，是新手入门 Skill 开发的最优场景之一。全程严格遵循「**创建目录 → 编写 YAML 配置 → 撰写技能正文 → 补充实战示例**」的标准化开发流程。

### 3\.1 第一步：创建标准 Skill 目录与文件

1、进入**用户级全局 Skill 目录**（全局生效，适配所有项目，新手首选）：

- CodeBuddy 默认路径：`~/.codebuddy/skills/`
- Claude Code 默认路径：`~/.claude/skills/`

2、新建技能专属文件夹，严格遵循**官方命名规范**：**小写英文\+连字符**，文件夹名称统一为`go-test-gen`。

3、进入该文件夹，创建技能核心配置文件，命名为 **SKILL\.md**（文件名、后缀固定不可修改，禁止使用 txt 等其他格式）。

新手最简标准目录结构如下：

```Plain
go-test-gen/
└── SKILL.md  # 技能核心配置与逻辑文件
```

### 3\.2 第二步：编写 YAML 头部配置（核心触发规则）

[YAML](https://yaml.org/spec/1.2.2/) 头部是 Skill 的核心「身份标识」，直接决定技能**识别、触发、匹配规则**。直接复制下方完整配置，粘贴至`SKILL.md` 文件顶部即可，无需手动调整格式。

本配置核心优势：**关键词精准、触发范围清晰、自带排他规则**，可大幅提升自动触发准确率，减少误匹配问题。

```yaml
---
name: go-test-gen
description: >
  为Go语言函数自动生成标准表驱动风格单元测试。
  当用户提出编写单测、生成测试用例、补充函数测试代码、完善单元测试等需求时自动触发。
  仅适用于Go语言项目，不处理其他编程语言的测试生成需求。
metadata:
  version: "1.0"
  author: "新手实战"
---
```

新手核心知识点解读：

- `name`：技能唯一标识，**必须与文件夹名称完全一致**，否则工具无法识别加载
- `description`：核心触发规则，写入用户高频口语化指令，精准锁定使用场景，同时明确排他边界
- **YAML 语法强制规范**：禁止使用 Tab 缩进，全程使用空格缩进，避免格式解析失败

### 3\.3 第三步：撰写完整 Skill 正文（套用通用模板）

在 YAML 头部配置下方，粘贴以下完整正文内容。正文严格复用前文通用模板结构，全覆盖**场景说明、分步流程、校验规则、实战示例**四大核心模块，可直接落地使用。

```markdown
# Go 单元测试自动生成技能
## 一、技能概述
本技能可快速为[Go语言](https://go.dev/)自定义函数生成行业标准的**表驱动风格单元测试**代码，统一团队测试代码格式，覆盖**常规、边界、异常全量测试场景**，解决新手手写单测不规范、场景缺失、重复编码的痛点，大幅提升Go项目测试开发效率。

## 二、前置条件
1. 当前项目为标准Go语言项目，可正常编译、运行，无环境报错
2. 待测试的Go函数代码完整、语法正确，可独立调用执行
3. 本地已配置完整Go开发环境，原生支持 [`testing` 标准库](https://pkg.go.dev/testing)

## 三、适用与不适用场景
✅ 适用场景：为Go自定义函数编写单元测试、补充缺失测试用例、优化完善现有单测代码
❌ 不适用场景：代码Bug修复、业务逻辑优化、文档编写、其他编程语言测试代码生成

## 四、分步执行步骤
### Step 1：解析目标函数
读取用户指定的Go文件与目标函数，精准梳理函数入参、出参、核心业务逻辑，明确本次测试的覆盖范围与核心校验点。
**检查点**：成功定位目标函数，无文件匹配、函数识别错误

### Step 2：规范生成测试代码
严格遵循Go官方单元测试规范生成代码，强制执行以下标准：
1. 仅使用原生 [`testing` 标准库](https://pkg.go.dev/testing)，不引入任何第三方测试框架
2. 测试函数命名统一规范为 `Test+原函数名`
3. 采用官方推荐 **`t.Run` 子测试 + 表驱动**标准化写法
4. 强制覆盖**正常输入、边界极值、异常输入**三类核心测试场景
**检查点**：生成代码格式规范、场景完整、无语法错误、符合Go编码标准

### Step 3：整理输出内容
自动格式化生成的测试代码，保留完整用例注释与场景说明，输出可直接复制运行、无需二次修改的完整代码。
**检查点**：输出代码可直接在项目中执行，无需手动调整格式与逻辑

## 五、代码示例（Before / After）
### 常规数值函数测试示例
**修改前（待测试原函数 Before）**
```go
func Add(a, b int) int {
    return a + b
}
```

**修改后（生成的单元测试 After）**

```go
func TestAdd(t *testing.T) {
	tests := []struct {
		name string
		a, b int
		want int
	}{
		{"正数正常相加", 1, 2, 3},
		{"零值相加", 0, 0, 0},
		{"负数相加", -1, -2, -3},
		{"正负混合相加", -1, 1, 0},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := Add(tt.a, tt.b); got != tt.want {
				t.Errorf("Add(%d, %d) = %d, 预期结果 %d", tt.a, tt.b, got, tt.want)
			}
		})
	}
}
```

## 四、核心功能精讲：Before/After 与检查点用法

![doubao_image_12_1781855387112.png](/images/doubao_image_12_1781855387112.png)

**Before/After 示例、分步检查点**是新手编写高质量 Skill 的**两大核心关键**，可从根本上解决 AI 自由发挥、执行逻辑混乱、输出格式不统一等常见问题，是标准化 Skill 开发的必备能力。

### 4\.1 Before/After 示例基础用法

核心设计逻辑：摒弃冗长的文字描述，通过「**修改前原始代码 \+ 修改后规范代码**」的直观对比，给 AI 明确的复刻标准，让 AI 严格按照示例格式与逻辑执行任务，是新手最好掌握、落地效果最优的写法。

新手强制使用规范：

- 所有**核心代码修改、生成类操作**，必须配套一组完整的 Before/After 对比示例
- 示例优先选用**通用常规场景**，逻辑简单、辨识度高，降低 AI 理解成本
- 所有代码块必须**精准标注对应编程语言**，保证工具格式识别准确

### 4\.2 检查点基础用法

核心设计逻辑：**分步校验、错即停止、逐段闭环**，每完成一步操作就校验执行结果，避免全流程执行完毕后才发现问题，大幅降低新手排错难度。

新手强制使用规范：

- 技能内每一个 Step 执行步骤，必须配置对应的**专属检查点**
- 优先使用**可直接执行的终端命令**作为校验依据，结果客观无歧义
- 无终端命令可校验的场景，需用清晰文字明确「**成功/失败**」的判断标准

### 5\.2 手动触发测试（精准兜底用法）

触发原理：用户主动输入专属命令，**强制调用指定 Skill**，无视语义匹配规则，可有效解决多技能冲突、自动匹配失误、触发不灵敏等问题，是问题排查、精准执行的兜底方案。

## 六、新手基础排错：常见问题与快速解决方案

![doubao_image_7_1781855414372.png](/images/doubao_image_7_1781855414372.png)

汇总新手首次开发 Skill 的**高频报错问题**，配套极简排查流程与落地解决方案，无需复杂调试，新手可快速自主修复。

### 问题1：完全不触发 Skill

高频原因 \& 对应解决方案：

- **文件路径错误**：检查技能文件夹是否直接放置在 `skills` 根目录，无多余嵌套层级
- **文件名称错误**：确认核心文件严格命名为 `SKILL.md`，大小写、后缀完全合规
- **YAML 格式错误**：检查头部`---` 首尾完整，无 Tab 缩进、无特殊乱码、无多余空行
- **描述过于笼统**：补充用户高频口语触发关键词，细化使用场景与边界规则

### 问题2：触发成功，但输出格式不标准

- **核心原因**：技能示例场景单一、执行规则描述模糊、无强制格式约束
- **解决方案**：补充多场景 Before/After 示例，细化每一步执行规则，增加格式强制约束语句

### 问题3：验证命令执行报错

- **核心原因**：本地未配置完整 [Go 环境](https://go.dev/)、当前项目非标准 Go 项目、项目文件缺失
- **解决方案**：完善本地 Go 开发环境，在合法可编译的 Go 项目目录下执行验证命令
