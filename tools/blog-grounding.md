# 选题定位提示词 · 以博客真实语境为锚（2026-10-30 重做版）

> 用途：给「选题雷达」与**任何想落稿的选题**用的**硬筛选提示词 + 可执行闸门**。它回答一个问题——
> 「这条候选（无论来自站外雷达、用户丢来的链接、还是自己想写），到底是不是**我的博客**该写的、且该先过标准？」
> 矩阵轴命中（AI×SEO×GEO×建站）只是「方向对」，不等于「贴我的博客」。
> 本提示词把「我的博客是谁、写什么、不写什么」落成可执行的判定规则，由 `blog-grounding.js` 在 KEEP 决策前强制过一道闸。

---

## 〇、铁律：凡要落入博客文章的选题，必须先过本判断标准

> 2026-10-30 用户拍板：**从现在起，任何选题在动笔/成稿之前，必须先跑 `groundingGate()` + `topic-fit-scorer()`（含真实需求数据层 `topic-demand`）。**
> - 来自选题雷达的候选：本就是流水线一环，自动过闸。
> - 来自用户丢来的链接 / 一句想法 / 自己灵光一现：**也必须先过闸**，再决定要不要写。
> - 闸门 verdict = `REFRAME` 或 `OFF` 的，不直接 KEEP；`REFRAME` 需先转译成「你（外贸独立站实操）怎么做」角度再立项；`OFF`（off-brand）直接 DROP。
> - 重复实验台：`node tools/topic-gate-experiment.js`（内置校准集含本博客认可的正例「33 个 Google SEO 实用工具」，随 51.la / GSC 真实数据滚动补充）。

## 二、判定规则（2026-10-30 重做：稳定 + 支柱/受众/需求三主线）

> 旧版两大坑（用户实测发现）：① 同一选题喂「标题」给 REFRAME、喂「正文」给 ALIGN（SPECIFIC_ANCHORS 子串硬匹配导致）——**不稳定**；
> ② 强制每条都带「瑞诚/塑料金属/询盘成本」锚点才放行——把用户认可的**支柱补位 + 受众真正需要的常青内容**（如面向外贸独立站运营者的 SEO 工具清单）**误杀成 REVIEW**。
> 新版改为：**支柱贴合 + 受众对口 + 真实需求** 任一即 ALIGN；具体一手锚点降为【加分 + 编辑建议】，不再拦截。

### ✅ ALIGN（贴我的博客 → 放行，可 KEEP/立项）
满足以下任一线即 ALIGN：
1. **命中我真实项目/业务**（瑞诚 / 询盘 / plasticxperts / custommetalpro / 本博客 SEO·GEO 技术）→ 直接 ALIGN（最高优先，覆盖一切）。
2. **支柱贴合 + 受众对口**：命中我实际栈/业务关键词（WordPress / Hexo / 自建站 / 外贸B2B / 谷歌SEO·Ads / GEO / AI 工作流 / 落地页转化 / 收录 / 排名 / 关键词 / 外链 等）**且**服务于目标受众（外贸独立站运营者 / SEO·GEO 从业者）。→ ALIGN。
3. **真实需求信号**：`topic-demand` 命中受众真实搜索词（demand > 0）→ 作为 ALIGN 置信加成。
- 以上任一线成立时，若**含一手角度锚**（瑞诚/双站/制造业B2B/询盘成本/真实踩坑/双站实测）→ 加分、注明「一手可信度强」；**若不含** → 给「建议补一手瑞诚·双站·制造业B2B 角度」的编辑提示（**非拦截项**，文章仍可立项）。

### 🔁 REFRAME（需转译才立项 → 不能自动 KEEP，降 REVIEW）
命中任一即 REFRAME（注意：这些看**来源/类型**，与上面 ALIGN 主线互不覆盖——步骤一判了 REFRAME 不会被主线覆盖回 ALIGN）：
1. **厂商·平台「发布了 X」**：标题是某产品/功能上新（introduces / launches / 推出 / 发布 / 新版），且不是「你怎么做」角度。例：`Introducing Yoast SEO AI+ for Shopify`。→ 你不是它的发布渠道，要转成「对外贸独立站通用的打法」才写。
2. **平台/巨头「改了 X」的新闻复述**：Google/微软/百度等「更新/调整/核心更新」。命中你支柱（外贸/独立站/SEO/GEO/Ads）且有「你怎么做/影响+自查」角度 → 转 ALIGN；只讲你不用平台或无一手角度 → REFRAME。
3. **只讲你不用/不评测的平台**：Shopify / BigCommerce / 有赞 等，且没落到你实际栈/受众 → 需转译成外贸独立站通用打法。
4. **泛 SEO·AI 资讯**：既不命中你实际栈/业务/受众，又无实操信号，也无真实需求数据 → 需你带外贸B2B独立站一手角度才立项。

### ⛔ OFF（红线 → DROP）
沿用 `topic-fit-scorer.js` 的 OFFBRAND（游戏/影视/股票/基金/理财/加密货币/政治/八卦/美妆/美食探店等）。本提示词不重复 DROP 非 off-brand 项，只把不贴博客的降到 REVIEW，避免误杀可转译题材。

## 三、为什么需要这道闸（踩过的坑 + 2026-10-30 重做）

原评分器只按「矩阵轴 + 外贸语境 + 操盘手信号」打分。结果：
- `Introducing Yoast SEO AI+ for Shopify` 因沾 AI×SEO 交叉 + "shopify" 是操盘手信号 → KEEP。但**你不用 Shopify**，这是厂商发布，不是你的博客。
- `Google Privacy Update → AI Mode Ads` 因含 "google/ads" 操盘手信号 → KEEP。但**你不是 Google 新闻博客**。
这两类占满「站外 KEEP」位，把真正的「你的博客一手选题」挤掉了。

2026-10-30 用户又发现**标准本身不稳、且过窄**：同一 SEO 工具选题喂标题判 REFRAME、喂正文判 ALIGN；且强制带业务锚点把「用户认可的常青选题」误杀。于是重做：
- **稳定**：同一选题无论喂标题还是正文，结论一致（不再因片段长度翻转）。
- **放宽误杀**：支柱+受众+需求三主线即 ALIGN；一手锚点降为加分/建议。
- **数据驱动**：接 `topic-demand` 真实需求层（51.la 搜索词 / GSC Queries / 必应站长 API），随用户「多沉淀、重复实验」滚动增长。
- **可重复实验**：`topic-gate-experiment.js` 内置校准集（含用户认可正例），反复跑看标准是否稳定、是否与真实 PV 一致。

本闸让 KEEP 位只留给：能写成「你（外贸独立站实操）怎么做」的题材；厂商发布/新闻复述/泛资讯统一降 REVIEW（单列「待改写角度」，等你带一手角度立项）。
